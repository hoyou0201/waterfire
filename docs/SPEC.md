# WaterFire — 게임 명세 (v0.4)

> "물불게임"(Fireboy & Watergirl, Oslo Albet, 2009~)에서 영감을 받은 **온라인 2인 협동** 퍼즐 플랫포머.
> 원작의 이름·캐릭터 디자인·아트·사운드·레벨은 사용하지 않고, 핵심 규칙만 참고해 새로 만든다.

### 변경 이력
- v0.4: MVP 구현 완료에 맞춰 정리. 레벨 해금은 순서형, 레벨 포맷 확정, 레벨 10개와 풀이 검증 방식 추가.
- v0.3: 개인용(본인 + 지인 1명)으로 범위를 줄임. 방 1개 고정 + 접속 암호. 기술 스택을 A안(TS 모노레포 + Colyseus)으로 확정.
- v0.2: 온라인 2인 전용으로 전환. 캐릭터끼리 밟고 올라설 수 있게 함. 플랫폼은 웹 브라우저로 확정.
- v0.1: 첫 초안

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 2D 협동 퍼즐 플랫포머 |
| 플랫폼 | 데스크톱 웹 브라우저 (키보드) |
| 인원 | **온라인 2인 전용.** 각 플레이어가 자기 브라우저에서 캐릭터 1개를 조작 |
| 사용자 | **개인용.** 본인과 지인 1명만 사용. 공개 서비스가 아님 |
| 핵심 재미 | 서로 다른 원소 제약을 가진 두 캐릭터가 서로를 도와야만 풀리는 퍼즐 |
| 한 판 길이 | 1~5분 |
| 목표 | 두 캐릭터가 각자의 출구에 **동시에** 도착 |

### 디자인 원칙
1. **비대칭 제약**: 한 캐릭터가 갈 수 있는 곳을 다른 캐릭터는 못 간다.
2. **상호 의존**: "한 명이 누르고, 다른 한 명이 지나간다", "한 명이 발판이 되어준다" 구조.
3. **즉시 재시도**: 한 명이 죽으면 둘 다 바로 레벨을 다시 시작한다.
4. **지연에 강한 퍼즐**: 온라인이므로 두 사람이 프레임 단위로 동시에 눌러야 하는 퍼즐은 만들지 않는다.

## 2. 범위

### MVP (v1)
- 고정된 방 1개 + 접속 암호, 캐릭터 선택
- 서버 권위 동기화 + 내 캐릭터 예측 (8장)
- 캐릭터 2종, 기본 물리, 캐릭터 간 충돌(밟고 올라서기)
- 지형: 벽/바닥, 경사면, 원소 웅덩이 3종
- 오브젝트: 보석, 출구, 레버, 압력 버튼, 이동 발판, 밀 수 있는 상자
- 레벨 10개 내외 (튜토리얼 포함)
- 결과 화면 (시간, 보석, 등급), 진행 저장

### 이후 (v2+)
| 분류 | 내용 |
|---|---|
| 빛 테마 | 광선, 회전 반사판, 광선 센서 |
| 얼음 테마 | 미끄러운 바닥, 얼음 ↔ 물 변환 |
| 크리스탈 테마 | 같은 색 포탈 간 순간이동 |
| 바람 테마 | 송풍기(상승 기류) |
| 레벨 변형 | 암흑 레벨(시야 제한), 타임어택 |
| 기타 | 퀵챗/이모트, 레벨 에디터, 게임패드 |

### 하지 않는 것
- 랜덤 매칭, 회원가입·계정, 친구 목록, 관전, 여러 방 동시 운영, 모바일 터치

## 3. 캐릭터 & 조작

| | 불 캐릭터 (Fire) | 물 캐릭터 (Water) |
|---|---|---|
| 안전한 액체 | 용암 | 물 |
| 즉사 액체 | 물, 독 | 용암, 독 |
| 먹을 수 있는 보석 | 빨강 | 파랑 |
| 출구 | 빨강 문 | 파랑 문 |

### 조작 (두 플레이어 공통, 각자 자기 캐릭터)
| 동작 | 키 |
|---|---|
| 이동 | ← → 또는 A D |
| 점프 | ↑ 또는 W 또는 Space |
| 메뉴 | Esc |
| 재시작 | R 길게 누르기 (8장 참고) |

### 캐릭터 간 충돌
- 두 캐릭터는 **단단한 몸**이다. 서로 겹쳐서 통과할 수 없다.
- **위에 올라서기**: 상대 머리 위에 착지하면 서 있을 수 있다. 아래 캐릭터가 움직이면 위 캐릭터도 함께 이동한다(이동 발판과 같은 방식).
- **올라선 채로 점프**: 위 캐릭터는 상대를 발판 삼아 점프할 수 있다. 3타일 높이 벽을 넘는 것도 퍼즐 요소로 쓸 수 있다.
- **옆으로 부딪힘**: 서로 밀 수는 없고, 벽처럼 막는다.
- **아래에서 부딪힘**: 위로 점프하다 상대 발바닥에 머리를 박으면 점프가 끊긴다.
- **원소 판정은 각자 독립**: 위 캐릭터는 아래 캐릭터가 서 있는 웅덩이에 닿지 않는다. 물 웅덩이 위에서 물 캐릭터가 불 캐릭터를 업고 건너는 퍼즐이 가능하다.
- **끼임 방지**: 좁은 통로에서 서로 막혀 영원히 갇히지 않도록 레벨 디자인 규칙으로 막는다. 최후 수단은 재시작이다.

## 4. 물리

타일 기반 월드. 아래 수치는 시작값이며 플레이테스트로 조정한다.

| 항목 | 값 (제안) |
|---|---|
| 타일 크기 | 32 px |
| 캐릭터 히트박스 | 약 0.75 × 1.25 타일 |
| 최대 수평 속도 | 약 6 타일/초 |
| 가속 / 감속 | 지상에서 빠르게, 공중에서는 약하게 (공중 제어 약 60%) |
| 최대 점프 높이 | 약 2.5 타일 (2칸 벽은 넘고 3칸은 못 넘음. 상대를 밟으면 넘음) |
| 가변 점프 | 점프 키를 일찍 떼면 낮게 뜀 |
| 코요테 타임 | 0.08초 |
| 점프 입력 버퍼 | 0.1초 |
| 경사면 | 45° 경사 지원. 멈춰 있으면 미끄러지지 않음 |
| 시뮬레이션 | **60Hz 고정 스텝, 결정론적.** 같은 입력이면 클라이언트와 서버에서 같은 결과가 나와야 함 (8장의 예측·보정 전제) |

- 물리 로직은 렌더링·네트워크와 분리된 **순수 함수 모듈**로 만든다. `step(state, inputs) → state` 형태이고, 서버와 클라이언트가 이 코드를 공유한다.

## 5. 지형 (타일)

| 타일 | 설명 |
|---|---|
| 벽/바닥 | 통과 불가 |
| 경사면 | 45° (좌상향, 우상향) |
| 용암 웅덩이 | 바닥에 파인 얕은 웅덩이. 불 캐릭터는 그냥 걸어서 지나감 |
| 물 웅덩이 | 물 캐릭터는 그냥 걸어서 지나감 |
| 독 웅덩이 | 둘 다 즉사 |

### 웅덩이 판정
- 웅덩이는 **반 타일 깊이**이고, 아래는 단단한 바닥이다. 빠지는 게 아니라 "안을 걸어서 통과"한다.
- 캐릭터 히트박스의 아래쪽 일부가 액체 영역과 겹치면 접촉으로 판정한다.
- 점프로 넘어가거나 상대 위에 올라타 있으면 닿지 않은 것으로 본다.

## 6. 오브젝트

| 오브젝트 | 동작 |
|---|---|
| **보석** | 같은 색 캐릭터가 닿으면 획득. 다른 색은 그냥 통과 |
| **출구 문** | 캐릭터별 1개. 두 캐릭터가 각자 문 앞에 동시에 서 있으면 레벨 클리어 |
| **레버** | 캐릭터가 밀고 지나간 방향으로 토글 (좌/우 두 상태). 상태가 유지됨 |
| **압력 버튼** | 캐릭터나 상자가 올라가 있는 **동안만** 켜짐 |
| **이동 발판 / 엘리베이터** | 연결된 스위치에 따라 위치 A ↔ B를 일정 속도로 이동. 위에 탄 캐릭터·상자를 함께 운반 |
| **장벽(게이트)** | 연결된 스위치가 켜지면 열림 (발판의 한 종류로 구현 가능) |
| **상자** | 캐릭터가 밀 수 있음. 중력 적용. 버튼을 누를 수 있음. 상자를 밟고 올라설 수 있음 |

### 스위치 ↔ 장치 연결
- 각 스위치(레버, 버튼)는 **채널**(색상 ID)을 가진다. 같은 채널의 장치가 반응한다.
- 같은 채널에 버튼이 여러 개면 **하나라도 눌리면 ON** (OR 조건).
- 스위치와 장치는 같은 색으로 칠해 연결 관계를 눈으로 알 수 있게 한다.

### 끼임 처리
- 이동 발판이 캐릭터를 벽에 짓누르는 경우 발판이 **멈춘다**. 캐릭터는 죽지 않는다.
- 캐릭터 둘이 쌓인 상태에서 천장에 눌리는 경우도 같다.

## 7. 레벨 진행 규칙

1. 두 플레이어가 모두 레벨에 들어오면 카운트다운(3초) 후 타이머가 시작된다.
2. 한 명이라도 죽으면 사망 연출(약 0.5초) 후 **둘 다** 레벨을 처음부터 다시 시작한다. 체크포인트는 없다.
3. 두 캐릭터가 각자 출구에 동시에 서 있으면 클리어된다.
4. 보석을 다 모으지 않아도 클리어할 수 있다.

### 평가 (등급)
| 등급 | 조건 |
|---|---|
| ★★★ | 보석 전부 + 목표 시간 이내 |
| ★★ | 보석 전부 **또는** 목표 시간 이내 |
| ★ | 클리어 |

- 목표 시간은 레벨 데이터에 넣는다.
- 기록(레벨별 최고 등급, 최단 시간, 최다 보석)은 **두 플레이어의 브라우저 양쪽에** 저장한다. 계정은 없다.
- 둘이 방에 모이면 서로의 기록을 **합친다**. 깬 레벨은 합집합으로, 기록은 더 좋은 쪽으로 정한다. 그래서 한쪽 브라우저 기록이 날아가도 상대 쪽에서 복구된다.

### 레벨 해금
- MVP는 순서형이다. 첫 레벨은 처음부터 열려 있고, 앞 레벨을 깨면 다음 레벨이 열린다. 분기형 맵은 레벨이 늘어나면 검토한다.
- 해금 상태는 위에서 합친 기록을 기준으로 한다.
- 클리어 화면에서 "다시 하기 / 레벨 선택 / 다음 레벨"을 고를 수 있다. 둘 중 누가 눌러도 함께 이동한다.

## 8. 온라인

### 8.1 방 흐름
개인용이라 **방은 서버에 딱 하나**만 있다. 초대 코드나 방 목록이 없다.

```
사이트 접속 → 암호·닉네임 입력(처음 한 번) → 대기실 → 캐릭터 선택(불/물) → 레벨 선택 → 플레이 → 결과 → 레벨 선택
```
- **접속 암호**: 서버 환경변수(`ROOM_PASSWORD`)에 정해 둔 암호를 맞혀야 들어올 수 있다. 사이트 주소가 알려지더라도 모르는 사람이 들어오지 못하게 하기 위해서다. 암호와 닉네임은 브라우저에 기억해서 다음부터는 바로 들어간다.
- **정원 2명**: 세 번째 접속은 "방이 꽉 찼습니다"로 거절한다.
- **캐릭터 선택**: 각자 원하는 캐릭터를 고른다. 이미 상대가 고른 캐릭터는 고를 수 없다. 레벨이 끝날 때마다 바꿀 수 있다.
- **레벨 선택**: 방장 개념 없이 **둘 중 누구나** 고를 수 있다. 고르면 상대 화면에도 표시되고, 둘 다 "준비"를 누르면 시작한다.

### 8.2 동기화 구조
**서버 권위(authoritative) + 클라이언트 예측**

```
클라이언트 A ──입력(틱 번호 포함)──▶ ┌────────────┐ ◀──입력── 클라이언트 B
              ◀──상태 스냅샷 20Hz── │ 서버: 방마다 │ ──스냅샷──▶
                                    │ 60Hz 시뮬    │
                                    └────────────┘
```
- **서버**: 방마다 게임 시뮬레이션을 60Hz로 돌린다. 판정은 서버가 확정한다(사망, 보석, 버튼, 클리어).
- **클라이언트 입력**: 매 틱 입력을 번호(seq)와 함께 보낸다. 입력은 비트 몇 개(좌/우/점프)라 매우 작다.
- **서버 입력 처리**: 플레이어마다 입력 대기열을 두고 틱마다 하나씩 꺼낸다. 대기열이 8개를 넘으면 오래된 것을 버리고, 15틱 동안 입력이 없으면 키를 뗀 것으로 본다. 스냅샷에 각 플레이어가 마지막으로 적용된 seq(ack)와 상대의 현재 입력을 담는다.
- **내 캐릭터**: 입력 즉시 로컬에서 예측해서 움직인다. 서버 스냅샷이 오면 그 시점부터 아직 확인되지 않은 입력을 다시 적용해 보정한다(reconciliation).
- **상대 캐릭터·오브젝트**: 서버 스냅샷을 약 100ms 늦게 보간해서 부드럽게 그린다.
- **사망·클리어 같은 이벤트**: 서버가 확정한 것만 연출한다. 예측으로 미리 죽이지 않는다.
- **밟고 올라서기와 예측**: 클라이언트는 상대 입력이 마지막 값 그대로 계속된다고 가정하고 월드 전체를 예측한다. 예측이 틀린 만큼은 화면에서 서서히 메운다(스무딩). 상대 위에 타고 있을 때 체감은 실제 플레이로 더 확인해야 한다.
- **화면 갱신이 멈출 때**: 틱은 보통 화면 갱신(requestAnimationFrame)마다 돌리고, 창이 가려져 갱신이 멈추면 타이머로 대신 돌린다.

### 8.3 연결 문제 처리
| 상황 | 동작 |
|---|---|
| 상대 연결 끊김 | 게임 일시정지 + "상대 재접속 대기 중" 표시. 60초 안에 돌아오면 이어서 한다 |
| 60초 초과 | 남은 사람은 대기실로 돌아간다. 상대가 다시 접속하면 대기실에서 이어서 한다 |
| 내 연결 끊김 | 자동으로 재접속을 시도한다. 성공하면 같은 방, 같은 캐릭터로 복귀한다 |
| 높은 지연 | 화면 구석에 핑 표시. 250ms가 넘으면 경고 아이콘 |

### 8.4 재시작·메뉴
- **재시작**: `R`을 1초 길게 누르면 재시작 요청이 된다. 상대 화면에 알림이 뜨고 **바로 재시작**한다. 동의 절차는 없다. 막힌 상황을 빨리 풀기 위해서다.
- **메뉴(Esc)**: 게임을 멈추지 않는다. 내 캐릭터만 입력이 멈춘다. 메뉴에서 계속하기 / 처음부터 다시 / 레벨 나가기를 고를 수 있다.
- **새로고침·탭 닫기**: 정상 퇴장으로 처리해서 자리를 바로 비운다. (재접속 대기 60초는 네트워크가 끊긴 경우에만)
- **레벨 나가기**: 누구나 할 수 있다. 확인 창을 띄우고, 나가면 둘 다 레벨 선택으로 돌아간다.

## 9. 레벨 데이터 포맷

JSON 파일. 타일 그리드는 문자열 행으로, 오브젝트는 목록으로 둔다. 서버와 클라이언트가 같은 파일을 읽는다.

```json
{
  "id": "01-first-steps",
  "name": "첫걸음",
  "hint": "레벨 선택 화면에 보여줄 한 줄 힌트",
  "targetTime": 25,
  "tiles": [
    "########################################",
    "#......................................#",
    "#....../#####\\.........................#",
    "#===LL====WW====GG=====................#"
  ],
  "spawns": { "fire": [2, 27], "water": [4, 27] },
  "objects": [
    { "type": "gem",    "color": "fire",  "pos": [10, 20] },
    { "type": "exit",   "color": "water", "pos": [36, 3] },
    { "type": "lever",  "channel": "yellow", "pos": [8, 27], "initial": "left" },
    { "type": "button", "channel": "purple", "pos": [15, 27] },
    { "type": "platform", "channel": "purple", "from": [20, 25], "to": [20, 18], "size": [3, 1], "speed": 2 },
    { "type": "box", "pos": [12, 26] }
  ]
}
```

| 문자 | 타일 |
|---|---|
| `#` | 벽 |
| `.` | 빈 공간 |
| `/` `\` | 경사면 |
| `L` | 용암 |
| `W` | 물 |
| `G` | 독 |
| `=` | 바닥 |

- 좌표는 타일 단위이고 원점은 좌상단이다. 크기는 `tiles`에서 정해진다 (현재 레벨은 모두 30×17).
- `spawns`, `exit`, `lever`, `button`, `box`의 `pos`는 "그 칸 바닥에 서 있다"는 뜻이다. `gem`은 그 칸 가운데에 뜬다.
- `platform`의 `from`/`to`는 발판 좌상단 칸, `size`는 [가로, 세로] 칸 수, `speed`는 타일/초(기본 2)다. 채널이 켜지면 `to`로, 꺼지면 `from`으로 움직인다. 문(게이트)도 발판으로 만든다.
- `lever`의 `initial`이 `"right"`면 켜진 상태로 시작한다.
- 웅덩이 타일(`L` `W` `G`)은 윗면이 바닥과 같은 높이이고, 그 위에 서면 접촉으로 판정한다.

### 레벨 만들기·검증
- `levels/*.json`은 `tools/genlevels.py`로 생성한다. 맵을 코드로 쌓아서 행 길이 실수를 막는다.
- 레벨마다 풀이 스크립트(`packages/shared/src/solutions.ts`)가 있다. 테스트가 실제 시뮬레이션으로 풀이를 돌려서 **보석을 모두 모으고 목표 시간 안에 깰 수 있는지** 확인한다. 레벨을 고치면 풀이도 함께 고친다.
- 목표 시간은 풀이 시간의 약 2.5배로 잡는다. 두 사람이 온라인으로 맞춰 움직이는 여유를 고려한 값이다.

### 현재 레벨
| # | 이름 | 배우는 것 |
|---|---|---|
| 1 | 첫걸음 | 이동, 점프, 자기 웅덩이 |
| 2 | 독 웅덩이 | 독 피하기, 지그재그로 오르기 |
| 3 | 누르고 지나가기 | 버튼과 문, 서로 눌러 주기 |
| 4 | 엘리베이터 | 버튼으로 움직이는 엘리베이터 |
| 5 | 상자 밀기 | 상자로 버튼 누르기, 디딤돌 |
| 6 | 어깨 빌려주기 | 상대를 밟고 오르기, 레버 |
| 7 | 비탈길 | 경사면, 내리막에서 뛰어넘기 |
| 8 | 업고 건너기 | 넓은 웅덩이를 상대 위에 타고 건너기 |
| 9 | 두 개의 레버 | 서로 상대의 문을 여는 레버 |
| 10 | 마지막 사원 | 업고 건너기 + 상자 + 엘리베이터 |

## 10. 기술 스택 (확정)

온라인 전용이라 **서버에서도 게임 시뮬레이션을 돌려야** 한다. 그래서 시뮬레이션 코드 하나를 서버와 클라이언트가 그대로 공유할 수 있는 TypeScript 모노레포로 정했다.

| 영역 | 선택 |
|---|---|
| 언어 | TypeScript |
| 패키지 관리 | pnpm workspaces |
| 클라이언트 | Vite + Canvas 2D (렌더링은 직접 구현) |
| 서버 | Node.js + Colyseus 0.18 (`@colyseus/core`, `@colyseus/ws-transport`) |
| 클라이언트 네트워크 | `@colyseus/sdk` |
| 테스트 | Vitest |

### 디렉터리 구성
```
packages/
  shared/   # 순수 시뮬레이션: 물리, 충돌, 오브젝트, 레벨 로더 (DOM·Node 의존 없음)
  client/   # 렌더링, 입력, 예측·보간, UI
  server/   # 방 관리, 60Hz 시뮬레이션 루프, 스냅샷 송신, 정적 파일 서빙
levels/     # 레벨 JSON
```
- `shared`는 Vitest로 단위 테스트한다. 같은 입력을 넣으면 같은 상태가 나오는지(결정론)도 검사한다.
- Colyseus의 상태 자동 동기화(Schema)는 쓰지 않는다. 대신 시뮬레이션 스냅샷을 메시지로 직접 보낸다. 시뮬레이션 상태를 한 가지 형태로만 관리하기 위해서다.

### 배포
- 서버 하나(Node 프로세스 1개)가 빌드된 클라이언트 정적 파일과 WebSocket을 **같은 주소에서** 함께 제공한다. 주소가 하나라 지인에게 링크 하나만 주면 된다.
- 호스팅 후보는 Q1에 정리했다.

## 11. 미결정 사항

- **Q1. 서버 호스팅** (MVP가 돌아간 뒤 결정):
  - Render 무료 플랜: 15분간 접속이 없으면 잠들고, 다시 깨어나는 데 약 1분 걸린다. 개인용이면 감수할 만하다.
  - Fly.io 등 소액 유료 플랜: 항상 켜져 있고, 월 몇 달러 수준이다.
  - 내 Mac에서 직접 실행 + Cloudflare Tunnel 또는 Tailscale: 무료지만 내 컴퓨터가 켜져 있어야 한다.
- **Q2. 아트 방향**: 일단 코드로 그린 단순한 도형으로 시작한다. 픽셀아트로 할지, 벡터 스타일로 할지는 나중에 정한다.
- **Q3. 레벨 제작 도구**: MVP는 JSON을 직접 편집한다. 레벨 수가 늘어나면 Tiled 가져오기를 검토한다.
