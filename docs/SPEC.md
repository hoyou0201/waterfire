# WaterFire — 게임 명세 (초안 v0.1)

> "물불게임"(Fireboy & Watergirl, Oslo Albet, 2009~)에서 영감을 받은 2인 협동 퍼즐 플랫포머.
> 원작의 이름·캐릭터 디자인·아트·사운드·레벨은 사용하지 않고, 핵심 규칙만 참고해 새로 만든다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 2D 협동 퍼즐 플랫포머 |
| 인원 | 로컬 2인 (키보드 1대 공유) / 1인이 두 캐릭터 동시 조작 |
| 핵심 재미 | 서로 다른 원소 제약을 가진 두 캐릭터가 서로를 도와야만 풀리는 퍼즐 |
| 한 판 길이 | 1~5분 |
| 목표 | 두 캐릭터가 각자의 출구에 **동시에** 도착 |

### 디자인 원칙
1. **비대칭 제약**: 한 캐릭터가 갈 수 있는 곳을 다른 캐릭터는 못 간다.
2. **상호 의존**: 대부분의 장치는 "한 명이 누르고, 다른 한 명이 지나간다" 구조.
3. **즉시 재시도**: 한 명이 죽으면 바로 레벨을 다시 시작한다. 로딩 없음.

---

## 2. 범위

### MVP (v1)
- 캐릭터 2종, 기본 물리
- 지형: 벽/바닥, 경사면, 원소 웅덩이 3종
- 오브젝트: 보석, 출구, 레버, 압력 버튼, 이동 발판, 밀 수 있는 상자
- 레벨 10개 내외 (튜토리얼 포함)
- 결과 화면 (시간, 보석, 등급), 진행 저장

### 이후 (v2+) — 원작의 "사원별 기믹"에 해당
| 테마 | 기믹 |
|---|---|
| 빛 | 광선, 회전 반사판, 광선 센서 |
| 얼음 | 미끄러운 바닥, 얼음 ↔ 물 변환 |
| 크리스탈 | 같은 색 포탈 간 순간이동 |
| 바람 | 송풍기(상승 기류) |
| 기타 | 암흑 레벨(시야 제한), 타임어택 레벨, 레벨 에디터, 온라인 협동 |

## 3. 캐릭터 & 조작

| | 불 캐릭터 (Fire) | 물 캐릭터 (Water) |
|---|---|---|
| 이동 | ← → | A D |
| 점프 | ↑ | W |
| 안전한 액체 | 용암 | 물 |
| 즉사 액체 | 물, 독 | 용암, 독 |
| 먹을 수 있는 보석 | 빨강 | 파랑 |
| 출구 | 빨강 문 | 파랑 문 |

- 공통 키: `Esc`/`P` 일시정지, `R` 재시작
- 두 캐릭터는 서로 **통과**한다 (서로 밟고 올라갈 수 없음). → 미결정 사항 Q3 참고
- 게임패드는 v2에서 지원

## 4. 물리

타일 기반 월드. 아래 수치는 시작값이며 플레이테스트로 조정한다.

| 항목 | 값 (제안) |
|---|---|
| 타일 크기 | 32 px |
| 캐릭터 히트박스 | 약 0.75 × 1.25 타일 |
| 최대 수평 속도 | 약 6 타일/초 |
| 가속 / 감속 | 지상에서 빠르게, 공중에서는 약하게 (공중 제어 약 60%) |
| 중력 | 고정값 |
| 최대 점프 높이 | 약 2.5 타일 (2칸 벽은 넘고 3칸은 못 넘음) |
| 가변 점프 | 점프 키를 일찍 떼면 낮게 뜀 |
| 코요테 타임 | 0.08초 |
| 점프 입력 버퍼 | 0.1초 |
| 경사면 | 45° 경사 지원. 멈춰 있으면 미끄러지지 않음 |
| 고정 업데이트 | 60Hz 고정 스텝 (결정론적, 리플레이·테스트 용이) |

## 5. 지형 (타일)

| 타일 | 설명 |
|---|---|
| 벽/바닥 | 통과 불가 |
| 경사면 | 45° (좌상향, 우상향) |
| 용암 웅덩이 | 바닥에 파인 얕은 웅덩이. 불 캐릭터는 그냥 걸어서 지나감 |
| 물 웅덩이 | 물 캐릭터는 그냥 걸어서 지나감 |
| 독 웅덩이 | 둘 다 즉사 |

### 웅덩이 판정
- 웅덩이는 **반 타일 깊이**이고, 아래는 단단한 바닥이다. 빠지는 게 아니라 "안을 걸어서 통과"한다.
- 캐릭터 히트박스의 아래쪽 일부가 액체 영역과 겹치면 접촉으로 판정한다.
- 웅덩이 위를 점프로 넘어가면 닿지 않은 것으로 본다.

## 6. 오브젝트

| 오브젝트 | 동작 |
|---|---|
| **보석** | 같은 색 캐릭터가 닿으면 획득. 다른 색은 그냥 통과 |
| **출구 문** | 캐릭터별 1개. 두 캐릭터가 각자 문 앞에 동시에 서 있으면 레벨 클리어 |
| **레버** | 캐릭터가 밀고 지나간 방향으로 토글 (좌/우 두 상태). 상태가 유지됨 |
| **압력 버튼** | 캐릭터나 상자가 올라가 있는 **동안만** 켜짐 |
| **이동 발판 / 엘리베이터** | 연결된 스위치에 따라 위치 A ↔ B를 일정 속도로 이동. 위에 탄 캐릭터·상자를 함께 운반 |
| **장벽(게이트)** | 연결된 스위치가 켜지면 열림 (발판의 한 종류로 구현 가능) |
| **상자** | 캐릭터가 밀 수 있음. 중력 적용. 버튼을 누를 수 있음. 상자를 밟고 올라설 수 있음 |

### 스위치 ↔ 장치 연결
- 각 스위치(레버, 버튼)는 **채널**(색상 ID)을 가진다. 같은 채널의 장치가 반응한다.
- 같은 채널에 버튼이 여러 개면 **하나라도 눌리면 ON** (OR 조건).
- 스위치와 장치는 같은 색으로 칠해 연결 관계를 눈으로 알 수 있게 한다.

### 끼임 처리
- 이동 발판이 캐릭터를 벽에 짓누르는 경우 발판이 **멈춘다**. 캐릭터는 죽지 않는다.

## 7. 레벨 진행 규칙

1. 레벨 시작 시 타이머가 시작된다.
2. 한 명이라도 죽으면 짧은 사망 연출(약 0.5초) 후 해당 레벨을 처음부터 다시 시작한다. 체크포인트는 없다.
3. 두 캐릭터가 각자 출구에 동시에 서 있으면 문이 열리는 연출이 나오고 클리어된다.
4. 보석을 다 모으지 않아도 클리어할 수 있다.

### 평가 (등급)
| 등급 | 조건 |
|---|---|
| ★★★ | 보석 전부 + 목표 시간 이내 |
| ★★ | 보석 전부 **또는** 목표 시간 이내 |
| ★ | 클리어 |

- 목표 시간은 레벨 데이터에 넣는다.
- 저장 데이터: 레벨별 최고 등급, 최단 시간, 최다 보석

### 레벨 해금
- 레벨 선택 화면은 분기형 맵이다. 레벨을 클리어하면 인접한 레벨이 열린다.
- 특정 레벨은 누적 별 개수로 해금한다(선택 사항).

## 8. 화면 흐름

```
타이틀 → 레벨 선택 맵 → 플레이 ─┬→ 결과 화면 → (다음 레벨 / 레벨 선택 / 재시도)
                               └→ 일시정지 (계속 / 재시작 / 레벨 선택 / 설정)
```

- HUD: 상단 중앙에 타이머만 표시. 보석 수는 결과 화면에서 보여준다.
- 설정: 사운드 볼륨, 키 리매핑(v2)

## 9. 레벨 데이터 포맷 (초안)

JSON 파일. 타일 그리드는 문자열 행으로, 오브젝트는 목록으로 둔다.

```json
{
  "id": "forest-01",
  "name": "첫걸음",
  "size": { "w": 40, "h": 30 },
  "targetTime": 60,
  "tiles": [
    "########################################",
    "#......................................#",
    "#....../#####\\.........................#",
    "#===LL====WW====GG=====................#"
  ],
  "spawns": { "fire": [2, 27], "water": [4, 27] },
  "objects": [
    { "type": "gem",    "color": "fire",  "pos": [10, 20] },
    { "type": "exit",   "color": "water", "pos": [36, 3] },
    { "type": "lever",  "channel": "yellow", "pos": [8, 27], "initial": "left" },
    { "type": "button", "channel": "purple", "pos": [15, 27] },
    { "type": "platform", "channel": "purple", "from": [20, 25], "to": [20, 18], "size": [3, 1], "speed": 2 },
    { "type": "box", "pos": [12, 26] }
  ]
}
```

| 문자 | 타일 |
|---|---|
| `#` | 벽 |
| `.` | 빈 공간 |
| `/` `\` | 경사면 |
| `L` | 용암 |
| `W` | 물 |
| `G` | 독 |
| `=` | 바닥 |

- 좌표는 타일 단위이고 원점은 좌상단이다.
- 레벨을 수작업으로 만들 때는 이 JSON을 직접 편집한다. 나중에 Tiled(.tmj) 가져오기나 자체 에디터를 고려한다.

## 10. 기술 스택 (제안 — 미확정)

| 선택지 | 장점 | 단점 |
|---|---|---|
| **TypeScript + Canvas (자체 엔진)** | 가볍고, 물리를 완전히 통제할 수 있고, 웹 배포가 쉬움 | 에디터·툴을 직접 만들어야 함 |
| TypeScript + Phaser 3 | 씬·입력·사운드가 이미 있음 | 기본 Arcade 물리는 경사면 처리가 약해 결국 커스텀이 필요 |
| Godot 4 | 에디터, 타일맵, 멀티플랫폼 빌드 | 웹 빌드가 무거움 |

**권장안: TypeScript + Vite + Canvas 2D 자체 구현.** 타일 물리는 단순해서 직접 만드는 쪽이 오히려 통제하기 쉽고, 고정 스텝 로직은 순수 함수로 분리해 단위 테스트할 수 있다. 결과물은 정적 웹페이지(GitHub Pages)로 배포한다.

## 11. 미결정 사항

- **Q1. 플랫폼**: 웹 브라우저 전용으로 할지, 모바일(터치)이나 데스크톱 앱까지 할지?
- **Q2. 기술 스택**: 10장의 권장안대로 갈지?
- **Q3. 캐릭터끼리 충돌**: 원작처럼 서로 통과하게 할지, 서로 밟고 올라설 수 있게 해서 새로운 퍼즐 요소로 쓸지?
- **Q4. 아트 방향**: 픽셀아트로 할지, 벡터/플랫 스타일로 할지?
- **Q5. 온라인 협동**: 로드맵에 넣을지? (넣는다면 처음부터 결정론적 시뮬레이션 + 입력 동기화 구조로 설계)
- **Q6. 레벨 제작 도구**: JSON 수작업, Tiled, 자체 에디터 중 무엇을 쓸지?
